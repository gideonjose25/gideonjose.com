The work

What happens to a server after it leaves the loading dock.

Every application a company runs lives on a machine somebody had to mount, cable, address, configure and protect. That somebody is me. Here is the job in six steps.

Step 01 · Rack mount

It arrives

A new server comes off the pallet. I fit the rails, seat it in the rack and check it against the build sheet before anything gets power. On one delivery that meant 30 servers at a single site.

Step 02 · Switches and cabling

It gets connected

I find free switch ports, record the switch, port, speed and cable type on the cabling sheet, then run the management and data cables. A server nobody can reach is furniture.

Step 03 · IP address administration

It gets an address

I reserve the management address in IPAM. Once, an address listed as free was already in use by a device nobody had registered. I traced it, documented it and got a clean one assigned.

Step 04 · Blade and rack servers

It gets an identity

Each week I migrate Cisco UCS blades from the old domain to a new Fabric Interconnect domain, and I move local service profiles to global in UCS Central. On Lenovo I set up the management controller. When a blade faults, I find the bad part and replace it.

Step 05 · Security

It gets protected

I turn on drive encryption across the server fleet and work in an environment fronted by Palo Alto firewalls and F5 load balancers. In the lab I take a vulnerability scan from finding to verified patch.

Troubleshooting

Cleared a stuck service profile association after a blade migration

Situation
During a weekly migration, I moved a Cisco UCS blade from the old domain into a new Fabric Interconnect domain and let discovery run to 100%.
Problem
I assigned its service profile from UCS Central, but it would not take. UCS Manager still showed the server as unassociated, and UCS Central had the profile stuck in Pending Reassociation.
Action
I re-acknowledged the server in UCS Manager, which sent it through discovery again.
Result
As soon as the second discovery reached 100%, the service profile associated with the blade. No other changes were needed.
Why it worked
Re-acknowledging makes UCS Manager rebuild its record of the blade from scratch. After a move between domains, that record can be left half-updated, so the association from UCS Central has nothing valid to attach to. A clean inventory lets the pending association go through.
